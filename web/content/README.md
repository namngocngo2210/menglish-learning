# Content bundles

Each `tests/*.json` file is a ContentBundle fragment containing arrays named `sources`, `passages`, `topics`, `questions`, and `tests`. See `lib/content/types.ts` for the strict Zod contract (unknown fields are rejected) and `tests/bank-grade-6.json` for an example. IDs are unique across files (topic identity is grade + skill + slug). References may cross files and are checked after merging. Topic/mixed tests use canonical four-segment route slugs; entrance tests use `thi-vao-lop-10/de-K`, grade 9 and no skill/topic fields. Tests store ordered question IDs and ISO publication timestamps. MCQs have four unique A–D options and one correct key.

The checked-in bank contains VOA Learning English public-domain material with source URL/name, license and crawl timestamp on every question. The old synthetic sample bundles have been superseded.

After reviewing quarantine, run `npm run build:tests` from `web/` as the explicit promotion step. It merges every quarantine fragment, creates published copies only in `content/tests/bank-grade-{6..9}.json`, and leaves quarantine unchanged. `bank-entrance.json` contains tests only, referencing the grade 8/9 bank. Shared sources/passages are stored once in the first grade file that references them; references are resolved after all files are merged.

Generation uses fixed string seeds (`grade/skill/topic/de-K`, or `thi-vao-lop-10/de-K`), a fixed publication timestamp (`2026-10-31T00:00:00.000Z`), stable sorting and two-space JSON with a trailing newline. Each test stores `seed`, `questionIds` in display order and `optionOrder`: a four-letter ABCD permutation per question. The loader applies permutations and remaps correct answers without changing the bank. Passage groups remain adjacent, with at most eight items per group in a test. Partitioning avoids repeating IDs within a topic/mixed set and across entrance tests; topic and mixed sets may reuse items.

Unused questions/resources and topics without tests are omitted. Questions used only in mixed/entrance tests retain their original classification even when that classification has no public topic page. Entrance loaders are available in Phase A; entrance page routes are added separately, so they are not yet included in the public sitemap.

Lifecycle: quarantine → draft → in_review → published; rejected and archived are excluded too. Only published questions reach the public loader. A test with any unpublished question is hidden in full. Topics, passages and sources without public content are removed. Quarantine lives outside `tests/`; it is never loaded publicly. Production content requires source/license verification and owner review.

The standalone crawler in `../../crawler/` follows the quarantine sink contract in `lib/content/importer.ts`. Its host-controlled sink accepts quarantine-only questions, no tests, and must validate and write only to `content/quarantine/`. It cannot publish. The crawler has its own CLI and no web write endpoint. Generated provenance fields are required by its bank gates and optional in the strict web schemas for backward compatibility.

The Node-only loader caches successful loads by absolute directory per process. Restart/rebuild after editing JSON; ISR re-renders cached content once an hour. For tooling/tests, call `loadBundle(directory)` or set `QUESTION_CONTENT_DIR` to another bundle directory. Default JSON files are explicitly included in Next server tracing; an override directory must be available at runtime (for example, mounted by the host). Invalid data errors include filenames and question IDs when available.


Owner approval for the VOA bank was given on 2026-10-31. Promotion writes `reviewNote: "owner-approved-bulk 2026-10-31"` and `reviewedAt: "2026-10-31T00:00:00.000Z"` alongside published status, preserving source URL/name, license and crawl time. These two fields are optional in the strict schema. Before partitioning, deterministic guards exclude duplicate options and narrowly defined cloze inflections/equivalent verb spellings; the CLI prints exclusions by reason and question/test counts by grade/kind. See [Guards](../../docs/content-sources.md#guards) for exact rules and corpus counts. Quarantine accepts duplicate option text for guard reporting; public questions must still have unique option text.
